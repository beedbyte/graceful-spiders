# 以根连接的 119 边臂图的完整内部零标号

**Beedbyte · 源码包 v1**

Jordi Gartner 通过 Beedbyte 发布这项工作。简体中文为翻译草稿，尚无记录表明经过人工语言审校。

## 固定 K119 定理

设 `H` 是边数为 `Q` 的任意有限带索引图，并给定常规优美标号 `g` 和指定根 `r`，满足 `g(r)=0`。将两条各长 119 条边的新臂连接到图上：把 238 边路径的中点（下标 119）与 `r` 识别。对任意整数深度 `d` 满足 `1≤d≤118`，路径下标 `119−d` 和 `119+d` 处的两个指定臂顶点均可在整个拼接图的常规优美标号中分别取值 0；每个目标使用各自的标号。边标号范围为 `238+Q`。

给定根标签为 0 是前提。`H` 不必连通、无环、为树、顶点满射标号或带 Alpha 标号；`Q=0` 也允许。结论不涵盖共享根、`H` 的旧顶点、深度119的新臂端点，也不声称两个目标能同时取 0。

## All-r 近尖端族

对每个 `r≥1`，令 `K_r=30·4^r−1`。复制源码闭包证明了对任意给定的常规优美标号有限图 `H`（指定根值为 0），在每条指定新 `K_r` 边臂上的下列四组深度处分别存在零标号：

| 源定理 | 深度 |
|---|---|
| `TerminalNormalized.rooted_both` | `K_r−8`、`K_r−7` |
| `TerminalSeed56.rooted_both` | `K_r−6`、`K_r−5` |
| `TerminalSeed34.rooted_both` | `K_r−4`、`K_r−3` |
| `TerminalSeed12.rooted_both` | `K_r−2`、`K_r−1` |

合起来是八个深度 `K_r−8,…,K_r−1`，每个目标均使用独立的目标相关标号。这只覆盖靠近臂端的这八个位置；它不证明 `r>1` 时的完整内部覆盖，也不适用于所有奇数臂长。固定的 `K119Through118.expanded` 定理另行证明 `K=119` 时全部内部深度 1–118。

## 证明组成与既有工作

固定 K119 定理将已冻结的 `K119Through114.interior`（深度 1–114）与两个末端种子族（115–116 和 117–118）合并。旧的 1–114 覆盖原样保存在 `source/K119Through114.lean`。两个新的 59 项种子词及其更正后的来源绑定包含在 `evidence/`；没有改写任何旧输入记录。

扩展末端归一化路径所用的是既有的端点匹配优美排列拼接方法，本包不声称提出新的拼接操作。其已发表的源流包括 [Hicks–Ollis–Schmitt 引理 4.5 的证明](https://community.middlebury.edu/~jschmitt/papers/HicksOllisSchmitt2018.pdf) 以及 [Adamaszek 引理 1](https://arxiv.org/pdf/math/0608513)。一般的 Alpha 拼接与根值为 0 的图也属既有构造，见 [Panpa、Imnang 和 Wasuanankul（2025），定理 2.5](https://onlinelibrary.wiley.com/doi/full/10.1155/jama/5826777) 和 [Shan–Zhong（2026），引理 1](https://arxiv.org/html/2605.14295v2)。两次应用 [Shan–Zhong 定理 2](https://arxiv.org/html/2605.14295v2) 已可得到任意 `H` 情形下两条指定臂深度 1 和 2 的结论；[Luiz–Campos–Richter（2017），定理 14](https://ic.unicamp.br/~reltech/2017/17-12.pdf) 覆盖中央附加一片叶子的特例。本文承认这些既有操作和特例。此前结果能否推出 K119 的完整深度范围 1–118 尚未解决；世界范围的优先权为 **UNKNOWN**。

## 复现与核验

本包包含传递源码闭包中的全部 68 个 Lean 模块、准确的模块顺序及 19 个控制模块：3 个正向检查和 16 个负向控制。`build.py` 接受 Lean 可执行文件路径和包外新建输出目录作为参数。它检查固定 Lean 4.34.0 的 SHA256、核验源码与控制文件、在全新对象目录中以警告视为错误进行编译，并运行 `Support`、`Positive`、`WholeClosure` 及 16 个语义变异控制。`check_path_guard.py` 检查输出路径及存在或失效的符号链接；`verify_package.py` 检查文件完整性。运行这些 Python 脚本时请使用 `python -B` 以免生成字节码缓存。无需网络或其他项目检出。

作者构建编译了全部 68 个源码，并统计了 2,809 个定理闭包，其依赖仅为 `propext`、`Classical.choice` 和 `Quot.sound`。另一次复制源码的独立内部重放重新编译了全部 68 个模块，检查五个主要定理，并拒绝了八个语义错误控制。作者测试还记录了 1,072 个具体命名实例和 16 个有效语义变异控制。这些均为项目内部核验，不是外部审查或同行评审。形式化信任边界包括 Lean 内核、编译器、标准库及编码后的图定义。冻结的作者报告和重放报告见 `evidence/`。
