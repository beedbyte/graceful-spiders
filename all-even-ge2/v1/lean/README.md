# Graceful labelings of even-arm spiders

**Beedbyte. Jordi Gartner owns and publishes this work.**

This package contains a Lean proof of the following statement. For every even integer `k ≥ 2`, every `n ≥ 2`, every `m ≥ 0`, and each specified vertex of the spider `S(k^n,1^m)`, there is a graceful labeling assigning zero to that vertex.

The graph consists of a common hub, `n` arms of `k` edges, and `m` additional one-edge arms. With `N = nk + m`, a graceful labeling assigns the vertex labels `0,…,N` bijectively and produces each absolute edge difference `1,…,N` exactly once. The labeling may depend on the chosen target vertex.

## Formal statements

The final declarations in `source/AllEvenGe2Closed.lean` are:

- `GracefulBoundary.Integration2Closed.all_even_ge_2_actual`
- `GracefulBoundary.Integration2Closed.all_even_ge_2_unique_zero`

Both quantify over the actual named `SpiderVertex n m k`: the hub, every vertex on every named long arm, and every existing short leaf. The second declaration also states that every other vertex has a positive label. The assumptions are exactly `2 ≤ k`, `k % 2 = 0`, and `2 ≤ n`, with `k`, `n`, and `m` natural numbers. Intermediate files retain conditional interfaces; the final declarations discharge their construction premises.

## Build

Requirements: Python 3.9 or newer and Lean **4.34.0**, including its installed standard libraries. No additional Lean project dependency is required. The build has been checked on Windows x86-64; other platforms are not covered by that check.

Verify the package without compiling:

```text
python build.py --check
```

Build all 186 modules into a directory that does not yet exist:

```text
python build.py --lean /path/to/lean --output /path/to/new-build-directory
```

If `lean` is already on `PATH`, omit `--lean`. Paths with spaces must be quoted according to your shell. The output directory must be outside this package. The script refuses an existing output directory; choose a new path for another build.

Before compiling, the script checks all package hashes, exact file inventory, source hashes and import order. It sets `LEAN_PATH` exclusively to the new output directory, removes `LEAN_SRC_PATH`, and invokes Lean with warnings treated as errors. Every source is compiled from the `source` working directory using its bare module filename. **Preserve this working-directory convention:** an internal audit checks a private Lean declaration whose name depends on the module root. The script records build commands, toolchain identity, logs and object hashes in the output directory, and rechecks package hashes after compilation.

`SHA256SUMS.txt` covers every other file in this package. `source-sha256.json` pins the 186 source files; `build-order.json` gives their topological order. Compiled objects and logs are generated by the build and are not included here.

## Methods and attribution

The formal development combines explicit path certificates, label and edge-weight inventories, recurrence arguments, graph attachment maps, and prescribed-zero constructions. Lean checks their proofs and the final graph-level composition. The checked axiom dependencies are the standard Lean axioms `propext`, `Classical.choice`, and `Quot.sound`.

Older constructional ingredients include graceful-permutation concatenation and balanced endpoint constructions: see [Hicks–Ollis–Schmitt, Lemma 4.5](https://community.middlebury.edu/~jschmitt/papers/HicksOllisSchmitt2018.pdf) and [Ollis, Lemma 5.5](https://ajc.maths.uq.edu.au/pdf/78/ajc_v78_p035.pdf). These references credit constructional ingredients. This package makes no claim of worldwide priority.

AI tools assisted Lean proof development, build tooling, and separately performed internal checks. These are internal project checks. A successful build establishes the stated formal proof within the documented Lean environment; it does not establish historical originality.
